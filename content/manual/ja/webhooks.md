# Webhook 送信ログ

取引の状態が変わると、加盟店の **システム通知先 URL** に Webhook（通知）を送ります。送信の記録・失敗の確認・再送はこの画面で行います。ペイロードの形式は [通知パラメータ仕様](/manual/notification-spec) を参照してください。

## 送信されるイベント

| イベント | タイミング |
|---|---|
| `payment.completed` | 取引が完了になったとき（手動完了・Webhook 受信・入金消込の一致 / 超過） |
| `payment.failed` | 取引が失敗になったとき |
| `payment.expired` | 振込期限超過で期限切れになったとき（毎時の自動処理を含む） |
| `payment.cancelled` | 取引がキャンセルされたとき |
| `refund.completed` | 返金が承認され完了したとき |
| `limit.exceeded` | 加盟店の限度額超過で取引が失敗として記録されたとき |
| `chargeback.opened` | チャージバックが登録されたとき |
| `subscription.*` | 定期課金の課金 / 失敗 / 停止 |

## 署名

| ヘッダー | 内容 |
|---|---|
| `X-Timestamp` | 送信時刻（UNIX 秒） |
| `X-Signature` | `v1=<HMAC-SHA256(鍵, "<X-Timestamp>.<ペイロード>") の16進>` |
| `Wirepay-Signature` | 互換用。`t=<X-Timestamp>,v1=<同じ値>` |

- **鍵** は加盟店の **署名シークレット**（加盟店詳細の APIキータブで発行。テスト / 本番それぞれ最新の有効なもの）です。署名シークレットが未発行の場合は加盟店パスワードを鍵に使います。
- **ペイロード** は POST（JSON / フォーム）ならリクエストボディそのもの、GET ならクエリ文字列（`?` の後ろ）です。
- 受信側は同じ計算で `v1` を求めて定数時間比較し、`X-Timestamp` が 5 分以上古い場合は拒否してください。

## リトライと断念

2xx 以外の応答、または **10 秒** 以内に応答が無い場合は失敗として記録し、**1 分 → 5 分 → 30 分 → 2 時間 → 24 時間** の間隔で最大 5 回まで自動再送します（期限が来たものは毎時の Cron `/api/cron/webhook-retry` が送信）。5 回失敗すると **断念** になり、トップページの「Webhook 失敗件数」に含まれます。

## 一覧・詳細・再送

- 一覧は失敗 / 断念 / リトライ待ちを上に表示し、加盟店・イベント・ステータス・期間で絞り込めます。CSV 出力あり。加盟店詳細の **Webhook送信ログ** タブにはその加盟店の直近の通知が表示されます。
- 詳細ではリクエスト（ヘッダー・ボディ）、最後の応答（先頭 1KB）、試行履歴（回数・応答コード・所要時間・きっかけ）を確認できます。
- **今すぐ再送**（マスター権限）はリトライ予定に関係なく新しい試行として直ちに送信します。断念した通知も再送でき、操作ログに記録されます。

## デモ用の受信エンドポイント

seed の加盟店は通知先が `/api/demo/webhook-receiver` になっています。クエリで応答を切り替えて動作を確認できます。

| クエリ | 応答 |
|---|---|
| `?result=ok` | 200（受信内容をエコー） |
| `?result=error` | 500（失敗 → リトライ） |
| `?result=timeout` | 12 秒待って応答（タイムアウト → リトライ） |
