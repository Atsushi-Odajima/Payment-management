# 定期課金

**課金プラン** に基づいて顧客に繰り返し課金する **定期課金（サブスクリプション）** を管理します。課金のたびに通常の取引が作成されるので、売上・返金・精算・レポートはすべて既存の画面で扱えます。

## 課金プラン

| 項目 | 説明 |
|---|---|
| 加盟店 | プランを持つ加盟店（作成後は変更不可） |
| プラン名 / 金額 | 1 周期あたりの請求額（円） |
| 課金周期 | 月額 / 年額 / 週額 |
| 無料期間 | 契約開始から課金を始めるまでの日数（0 で即日課金） |
| 有効 | 無効にすると新しい契約を開始できません（既存の契約はそのまま課金を続けます） |

プランは **＋ プランを作成** で作り、一覧の名前から編集できます。金額や周期の変更は次回以降の課金に反映されます。

## 契約の開始とステータス

**＋ 契約を開始** で有効なプランと顧客 ID・氏名・メールアドレスを入力します。ヘッダーのテスト / 本番スイッチが契約のモードになります。

| ステータス | 意味 |
|---|---|
| 無料期間（trialing） | 無料期間中。終了日が次回課金日になります |
| 有効（active） | 次回課金日に自動で課金されます |
| 未払い（past_due） | 直近の課金が失敗し、再試行を待っています |
| 停止（suspended） | 3 回連続で失敗、または一時停止中。再開するまで課金されません |
| 解約（cancelled） | 終了。再開できません |

## 課金と再試行

- 毎時 15 分の cron（`/api/cron/subscriptions`）が **次回課金日を過ぎた** 有効 / 無料期間 / 未払いの契約を課金します。
- 課金は加盟店のクレジット決済プロバイダ（同じモード）で取引を作成し、成功すると取引は **完了**、次回課金日が 1 周期進み、加盟店に Webhook `subscription.charged` を送ります。
- 失敗すると失敗回数を +1 し、**3 日後 → 7 日後** に再試行します（Webhook `subscription.payment_failed`、顧客へ「課金失敗」メール）。3 回目の失敗で **停止** になり、Webhook `subscription.suspended` と「停止」メールを送ります。
- 詳細画面の **今すぐ課金（成功）** / **今すぐ課金（失敗をシミュレート）** は結果を指定して同じ処理を実行します。**一時停止** → 停止、**再開** → 有効（直ちに課金対象）、**解約** は取り消せません。
- デモの課金失敗率は一覧画面の **デモの課金失敗率**（マスターのみ）で変更できます。cron と「今すぐ課金」の既定動作にこの確率で失敗が混ざります。

課金で作成された取引は取引詳細に「定期課金」として表示され、返金やチャージバックは通常の取引と同じ手順です。

## 権限

| 操作 | マスター | 一般 |
|---|---|---|
| 閲覧 | ○ | ○ |
| プランの作成・編集、契約の開始 | ○ | ○ |
| 今すぐ課金・一時停止・再開・解約 | ○ | × |
| デモの課金失敗率の変更 | ○ | × |

すべての変更は操作ログに記録されます（`plan.*` / `subscription.*`）。
