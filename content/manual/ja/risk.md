# リスク対策

チャージバック、ブラックリスト（連続失敗の自動検知）、過不足入金の 3 つの画面です。いずれもヘッダーの **テスト / 本番** スイッチで対象データが切り替わります。

## チャージバック

カード会社からの支払異議を登録し、異議申立てと結果を管理します。登録・異議申立て・結果登録はすべて **マスター権限** です。

| ステータス | 意味 | 次の操作 |
|---|---|---|
| 受付 | チャージバックを登録した直後 | 異議申立て（証憑メモ必須）/ 確定する |
| 異議申立中 | 証憑を添えて異議を申し立てた | 勝訴を登録 / 敗訴を登録 / 確定する |
| 勝訴 | 異議が認められた。取引は完了のまま | — |
| 敗訴 | 異議が退けられた。取引は **チャージバック** になる | 確定する |
| 確定 | 最終確定。取引はチャージバック、精算で控除 | — |

- 登録は取引詳細の「チャージバックを登録」またはチャージバック一覧の **チャージバックを登録** から行い、対象取引（完了 / 一部返金 / 返金済）・異議金額・理由コード（不正利用 / 商品未着 / 商品相違 / 重複請求 / その他）・異議申立期限（既定 14 日後）・証憑メモを入力します。登録時に加盟店へ `chargeback.opened` の Webhook を送ります。
- 一覧は対応中（受付・異議申立中）を上に、異議申立期限が近い順に表示し、期限まで 3 日以内は赤で強調します。
- 敗訴・確定した金額は [精算管理](/manual/settlements) のバッチ生成時に「チャージバック合計」として差し引かれます。

## ブラックリスト

カード・IP・メールアドレスの拒否リストです。

- **連続失敗の検知ルール**（マスター）: 同じカード識別ハッシュ / 接続元 IP / メールアドレスで直近 N 分に M 回失敗すると、自動で **候補** として登録されます（既定 10 分 / 3 回）。候補はトップページとリスクメニューのバッジに表示され、マスターが **承認** すると有効、**却下** すると無効化されます。
- **手動追加**（マスター）: 値を入力するとすぐに有効になります。カードは取引のカード識別ハッシュ（デモでは `ブランド|下4桁|有効期限` の SHA-256）、IP は IPv4、メールは小文字で照合します。
- 有効な項目に一致する決済申請は作成時に **失敗（ブラックリストによりブロック）** として記録されます（取引詳細の失敗理由に種別を表示）。有効 / 無効はいつでも切り替えられます。
- 取引の作成 API はデモ用のカード情報（ブランド・下 4 桁・有効期限）と接続元 IP を受け取り、取引詳細に「カード下4桁」「接続元 IP」として表示します。横断検索はカード下 4 桁でも検索できます。

## 過不足入金

入金消込で **不足** または **超過** が発生した銀行振込を一覧化し、対応状況を管理します。

| 対応状況 | 意味 |
|---|---|
| 未対応 | 消込直後（自動で登録） |
| 差額返金手配中 | 超過分の [返金申請](/manual/refunds) を作成した（マスターの承認後に返金） |
| 追加入金案内済 | 不足分の追加入金をユーザーに案内した（メールテンプレートで送信・記録） |
| 完了 | 対応が終わった |

- 超過: **差額を返金申請** で超過額の返金申請（理由: 重複決済）を自動生成します。
- 不足: **追加入金を案内済にする** で案内済みにします。ユーザーが不足分を振り込むと入金消込で完了になります。
- どちらも **完了にする** で対応を閉じます。未対応件数はトップページに表示します。
