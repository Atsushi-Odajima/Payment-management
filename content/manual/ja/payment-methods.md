# 決済手段の停止

決済事業者側の障害や加盟店からの依頼で、**特定の決済手段の新規申請だけを一時的に止める** 機能です。進行中の取引（完了・返金・入金消込など）には影響しません。

## 判定の順序

1. **全体停止**（設定 → 決済手段の停止管理、admin のみ）
2. **加盟店別停止**（加盟店詳細 → 決済手段タブ、admin / cs）
3. 加盟店の **利用可能な決済手段**（基本情報）

3 つすべてを通った手段だけが受け付けられます。判定は取引作成の共通処理で行われるため、管理画面の「決済を作成」、決済リンクの決済ページ、定期課金の課金、加盟店向け API とサンドボックス（フェーズL）のすべてに同じ結果が適用されます。停止中の手段は決済ページと作成フォームの選択肢から消え、API で指定された場合は `409 method_suspended` を返します。

## 停止と再開

- 対象はクレジット / QR / コンビニ / 銀行振込の 4 種類です（「その他」のプロバイダにはスイッチがありません）。
- スイッチを停止側に切り替えるとモーダルが開き、**理由（必須）** と **自動再開予定日時（任意）** を入力しないと停止できません（全体・加盟店別とも同じ）。自動再開は cron（`/api/cron/payment-method-controls`）がその時刻以降に行います。停止中の行には理由・停止者・停止日時・再開予定を表示し、加盟店管理画面の「決済手段の状態」にも同じ内容が出ます。
- 停止・再開はすべて操作ログ（`payment_method.suspend` / `payment_method.resume`）に記録され、通知センター（フェーズJ）に通知を作成します（全体停止は critical、加盟店別は warning）。
- **全体停止中** はトップページと全画面のヘッダーに赤いバナーが表示されます。
- 全体停止を行うと「障害情報のお知らせ下書きを作成しますか」と確認され、Yes を選ぶと障害（incident）の下書きが作られて編集画面に移動します。公開は編集画面で行います。

## API

| リクエスト | 権限 | 内容 |
|---|---|---|
| `GET /api/payment-method-controls` | 閲覧 | 全体の 4 スイッチ |
| `GET /api/payment-method-controls?merchantId=<id>` | 閲覧 | 全体 + その加盟店のスイッチ |
| `PUT /api/payment-method-controls` `{ scope: "global" | "merchant", merchantId?, method, suspended, reason, resumeAt? }` | global = admin、merchant = admin / cs | 停止（理由必須）/ 再開 |

停止中の手段で取引を作ろうとした場合の応答: `409 { code: "method_suspended", details: { scope: "global" | "merchant", method } }`。
