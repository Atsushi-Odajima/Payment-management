# 加盟店管理

加盟店（EC サイト運営者）のアカウントを発行・管理します。

## 一覧

加盟店 ID・サイト名・会社名・担当者名・担当代理店・メール通知設定・登録日を表示します。行をクリックすると詳細画面へ移動します。20 件ごとにページ送りされます。

## 加盟店の追加

右上の **＋ 加盟店追加** から登録します。

| 項目 | 説明 |
|---|---|
| 加盟店 ID | `MER-00001` 形式で自動採番。変更できません |
| 加盟店パスワード | 登録時に自動生成され、暗号化して保存されます。画面では常に `********` |
| サイト名 / ふりがな | ふりがなは **全角カタカナのみ** |
| 会社名 / 担当者名 | 必須 |
| 担当代理店 | 任意。代理店管理に登録済みの代理店から選択 |
| メールアドレス / 明細送付先 | 形式を検証。「メールアドレスと同じ」で複製できます |
| システム通知先 URL | 決済結果を送る加盟店側エンドポイント。**https のみ** |
| 通知パラメータ設定 | 通知の型 / 送信パラメータセット / 決済識別子の形式（詳細は「通知パラメータ仕様」） |
| メール通知設定 | 決済ごと / 1 日まとめて通知 / メール通知無し |

必須項目が揃うまで「登録する」は押せません。エラーがある場合は該当項目の下にメッセージが表示され、最初のエラー項目までスクロールします。

## 詳細と編集

詳細画面は **閲覧モード** で開きます。右上の **編集** を押すと編集モードになり、最下部の **更新** で保存します。保存後は自動で閲覧モードに戻ります。

- 加盟店 ID とパスワードは編集できません。
- **パスワードの表示（目のアイコン）と再発行** はマスター権限のみ使えます。一般権限ではボタンが無効になり、API も 403 を返します。
- 再発行すると旧パスワードは無効になります。表示された新しい値を加盟店に連携してください。

## 利用可能な決済手段

「利用可能な決済手段」と「振込IDの桁数」は加盟店フォームの **決済設定** で編集します。振込IDの桁数（7 桁または 8 桁）は、この加盟店の銀行振込の取引に発行される振込IDの長さです。

## タブ構成

詳細画面は 5 つのタブに分かれています。**基本情報** と **通知設定** は右上の「編集」で加盟店フォームを開き、他のタブはそれぞれ専用の入力欄を持ちます。

| タブ | 内容 |
|---|---|
| 基本情報 | 加盟店 ID・パスワード・サイト / 会社 / 担当者・担当代理店・利用可能な決済手段・振込IDの桁数・連絡先 |
| 契約・手数料 | 契約プランと決済手段ごとの手数料率、適用開始日、契約履歴、振込期限・返金可能期限 |
| 限度額 | 決済手段ごとの 1 回 / 1 日 / 1 か月の限度額と、本日・今月の利用状況 |
| APIキー | 加盟店サイトが決済 API を呼ぶための API キーと、通知の署名シークレット |
| 通知設定 | システム通知先 URL・通知の型・パラメータセット・識別子と通知サンプル |

## 契約・手数料

| 項目 | 説明 |
|---|---|
| 契約プラン | **スタンダード** / **プレミアム** は既定の料率が自動で入り、**カスタム** は決済手段（クレジット / QR / コンビニ / 銀行振込）ごとに料率（%・小数 2 桁）と固定手数料（円/件）を入力します |
| 適用開始日 | 指定日の 0:00（日本時間）から新しい料率が適用されます。未来日を指定すると **適用予定** として登録され、当日まで現在の契約が有効です |
| 契約履歴 | 過去の契約は削除せず履歴として残り、適用中 / 適用予定 / 終了のバッジで区別します |
| 振込期限（日） | 銀行振込の申請から振込期限までの日数（1〜60、既定 7）。**新しく作成する取引** に適用されます |
| 返金可能期限（日） | 完了日からこの日数以内であれば返金できます（0〜365、既定 180）。取引詳細に **返金可能期限** として表示します |

契約の登録・期限の変更はすべて [操作ログ](/manual/admins) に変更前後の値とともに記録されます。

## 限度額

決済手段ごとに **1 回あたり** / **1 日あたり** / **1 か月あたり** の上限金額を設定します（空欄は無制限）。上部のカードには表示中のモード（テスト / 本番）での本日・今月の取扱高と消化率を表示します。

限度額を超える取引は加盟店サイトからの申請時に **失敗** として記録され、取引詳細の「失敗理由」に「1 回あたり / 1 日あたり / 1 か月あたりの限度額を超過」と表示されます（一覧では「限度額超過」バッジ）。失敗・キャンセル・期限切れの取引は限度額の消化に含めません。

## APIキー

| 項目 | 説明 |
|---|---|
| モード | **テスト** / **本番**。キーの先頭（`wp_test_…` / `wp_live_…`）で見分けられます |
| 種別 | **API キー**（加盟店サイトから決済 API を呼ぶ Bearer トークン）/ **署名シークレット**（通知の署名検証に使う共有鍵） |
| 発行 | 発行直後の画面で **1 回だけ** 平文を表示します。DB には SHA-256 ハッシュのみ保存するため、閉じると再表示できません |
| ローテーション | 同じモード・種別・ラベルで新しいキーを発行し、旧キーは **猶予期間**（既定 7 日、0〜90 日）の間だけ併用できます。期限が来ると自動的に **期限切れ** になります |
| 失効 | 直ちに無効化します。失効したキーはローテーションできません |
| 最終利用 | 加盟店 API がキーを受け付けた最終日時 |

疎通確認には `GET /api/merchant-api/ping` を使います。`Authorization: Bearer <API キー>` で呼ぶと加盟店 ID・モード・ステータスを返し、その加盟店向けの [IP制限](/manual/ip-restrictions)（加盟店 API・ブロック）にも従います。

## テスト / 本番の切替

ヘッダーの **テスト / 本番** スイッチは、決済一覧・決済申請一覧・ダッシュボード・限度額の利用状況が参照するデータモードを切り替えます（選択は Cookie に保存）。取引はプロバイダのモードを作成時にスナップショットしており、テストモードでは本番の取引は表示されません。
